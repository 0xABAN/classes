# A tiny language model in Oz

Adam Torres · CMPSC 448 · Homework 3

This project trains a small decoder-only Transformer from random weights on L. Frank Baum's *The Wonderful Wizard of Oz*. It predicts the next **character**, then generates a continuation one character at a time. It is a story-completion model, not a chatbot.

## Run the live demo

From this directory:

```sh
uv sync --frozen
uv run python -m ozlm.generate
```

The trained model is saved in `artifacts/model.pt`. Generation runs on the CPU without network access. Dependencies must already be installed before the recitation. To run without even checking the package registry, use:

```sh
.venv/bin/python -m ozlm.generate
```

Try these openings, one at a time:

- `Dorothy said`
- `The Scarecrow`
- `The Wizard of Oz`
- `Once upon a time`

Type `/quit` to exit. Empty prompts and characters outside the training alphabet produce an explicit error. Prompts longer than 128 characters are accepted; only their last 128 characters influence the next prediction.

A single generation:

```sh
uv run python -m ozlm.generate --prompt "Dorothy said" --length 300
```

To explore sampling, compare `--temperature 0.5` and `--temperature 1.0`. Lower temperature favors the model's most probable characters. Higher temperature makes less probable characters more likely, often introducing more errors. The default sampling seed is fixed so demonstrations are repeatable; change it with `--seed 7`.

## What to explain to the TA

1. **Data:** I downloaded a book from Project Gutenberg. Preprocessing removes the license, front matter and illustration labels. The original download is retained with its license in `data/pg55.txt`.
2. **Tokens:** Each character is a token. The alphabet is fitted only on training text. Characters make a small, understandable vocabulary, but 128 characters cover much less text than 128 word-piece tokens.
3. **Training:** A window is the input; the same window shifted one character forward is the target. Cross-entropy penalizes wrong next-character predictions. Gradient descent updates randomly initialized weights. No pretrained model, embeddings or tokenizer is used.
4. **Architecture:** Three Transformer blocks, four attention heads, 128-dimensional embeddings and a 128-character context. Causal attention masks future characters so training cannot read the answer. Residual connections, layer normalization and dropout support training.
5. **Validation:** The first 90% of the story is training text and the final 10% is validation text. Windows never cross that boundary. The checkpoint with the lowest sampled validation loss is retained. This validation set selects the checkpoint; it is not an independent test set.
6. **Generation:** The model predicts a distribution over the next character, samples among the 20 most likely choices, appends one character and repeats. Text is generated by the saved model, not retrieved from a list of canned answers.
7. **Limits:** A tiny model trained on one book can learn spelling, frequent names and dialogue patterns while still producing nonsense. Repeated training may memorize passages. Loss reduction does not prove understanding or useful question answering.

## Completed training run

The October 22 run trained 628,932 parameters for 3,000 steps on CPU in 484 seconds. Sampled validation loss fell from 4.2870 to 1.3120; step 3,000 was the best checkpoint. Reloading the saved weights reproduced that validation loss, and the interactive command generated fresh continuations for three prompts. All nine pipeline tests passed.

The untrained model emits random characters. After training, it uses names such as Dorothy and the Tin Woodman and imitates dialogue, but still makes spelling errors, repeats phrases and loses coherence. See `artifacts/samples.json` for the fixed-seed before/after outputs.

## Reproduce training

```sh
uv run python -m pytest tests -q
uv run python -m ozlm.data
uv run python -m ozlm.train --output artifacts/retrained
```

The default run performs 3,000 optimizer steps with batches of 24 windows. It uses AdamW, a short warmup followed by cosine learning-rate decay, and gradient clipping. Evaluation uses the same seeded windows every 250 steps. The training seed is 448. Full settings and measured losses are recorded in `artifacts/training.json`; untrained and trained generations are in `artifacts/samples.json`.

Training defaults to CPU. Apple GPU training is an explicit option (`--device mps`); it errors if unavailable. The published results describe the device actually used. Existing checkpoints are never overwritten: choose a new output directory for another run. Full numerical reproducibility can vary across machines and library versions.

The downloaded source is checked against a recorded SHA-256 hash. If the publisher changes the edition, preparation stops rather than silently training on different text. `data/metadata.json` records the URL, hashes, split sizes and vocabulary size.

## Files

- `ozlm/data.py`: download verification, cleanup, tokenizer and training windows.
- `ozlm/model.py`: causal Transformer initialized from scratch.
- `ozlm/train.py`: optimization, validation and checkpoint selection.
- `ozlm/generate.py`: checkpoint loading and interactive generation.
- `tests/test_pipeline.py`: causality, target alignment, tiny-corpus learning, checkpoint round-trip and command checks.
